# 瘦身與防增肥守則（Anti-Bloat Guidelines）

> **宗旨：Vercel 儲存空間與部署配額是有限資源。每次改版前先讀本文件，避免專案「增肥」。**
> 本守則於 2026-09-20 專案大瘦身時建立；之後任何 PR 都應符合以下規範。

---

## 一、依賴守則（package.json）

1. **新增任何 dependency 前必須回答三題**（答不出來就不准加）：
   - 這個功能能不能用 ≤ 30 行自有程式碼或瀏覽器原生 API 做到？（本專案的 QR Code、音效、動畫都是自製的，保持這樣）
   - 它的 install size（含 transitive deps）是多少？（用 `npm i --no-save <pkg> && du -sh node_modules/<pkg>` 量）超過 **5 MB** 需要充分理由。
   - 它是 **runtime 需要** 還是 **只有 build/test 需要**？
2. **只有建置期使用的工具一律放 `devDependencies`**：Vite、Tailwind（`tailwindcss`、`@tailwindcss/vite`）、ESLint、Vitest、TypeScript、所有 `@types/*`。
   - `dependencies` 目前**只准**包含真正被 bundle 進產物的運行期套件：`react`、`react-dom`、`react-router-dom`、`lucide-react`、`qrcode`。
3. **禁止安裝從未被 import 的套件**。已發生的教訓：`framer-motion`（連同 `motion-dom`、`motion-utils` 共 ~10 MB）躺在 dependencies 裡 **0 次引用**，2026-09-20 已移除。新增套件後請立刻寫出使用它的程式碼，同一個 PR 內完成。
4. 定期檢查：`npx depcheck`（或人工 grep 每個 dependency 名稱）確認沒有殭屍依賴。
5. **lockfile 必須隨 package.json 一起 commit**（Vercel 用 `npm ci` 安裝，缺 lockfile 會 build 失敗）。

## 二、靜態資源守則（public/ 與 src/assets/）

1. **`public/` 只放會被直接引用的檔案**。放入前先 grep 確認有引用點。
   - 2026-11-12 起：favicon 改用 **G11 標準九個 PNG/ICO 實體檔**（`public/icons/`，合共 ≤ 260 KB），`index.html` 掛載 `favicon.ico` / `favicon-16/32.png` / `apple-touch-icon.png` / `manifest.webmanifest`；**不要**再改回 inline data-URI SVG favicon（iOS 主畫面／PWA 安裝不支援）。
   - 已發生的教訓：`public/favicon.svg`（824 B）從未被引用，2026-09-20 已移除。
2. **嚴禁 commit**：高解析度截圖、設計原稿（PSD/Figma 匯出）、展示用圖、影片、`uploads/`、任何使用者測試資料。展示素材放 issue/PR 討論串或外部圖床，不入 repo。
3. 圖片素材優先順序：**inline SVG / data-URI / Emoji ＞ 向量檔 ＞ 壓縮後的 raster**。 raster 圖一律先壓縮（tinypng 等）再入庫。
4. 單檔 > 200 KB 的二進位檔需要充分理由並在 PR 說明。
5. `public/_redirects` 是 Netlify SPA fallback（README 部署章節有引用），**保留**；Vercel 端由 `vercel.json` rewrites 處理。

## 三、死重程式碼守則（src/）

1. **不准留備份檔**：`*.bak`、`*.tmp`、`*.old`、`*.orig`、`*.rej`、`copy-of-*`、`*-backup.*` 一律不准進 repo。備份是 git 的工作（`git log` / branch）。
2. **孤兒模組要即殺**：新增的 util/hook/lib 若最終沒被 import，同 PR 內刪除。
   - 2026-09-20 移除的孤兒檔（全部經 grep 全庫驗證 0 引用）：
     | 檔案 | 原因 |
     |---|---|
     | `src/apps/kims/hooks/useGame.ts` | `useTimer`/`useLocalStorage`/`useImageUpload` 無人使用；KimsApp 曾呼叫 `upload(files)` 把上傳圖片多讀一份 base64 存進**從未渲染**的 state（純記憶體浪費），已一併移除 |
     | `src/apps/kims/hooks/useFullscreen.ts` | 無人使用，且本身有 listener 洩漏 bug（每次 render 加一個 `fullscreenchange` 監聽、從不移除）——刪档即滅蟲 |
     | `src/apps/photo/lib/broadcast.ts` | 無人使用的 `getBroadcastChannel` wrapper |
3. 每次改版後可跑這個一鍵孤兒檔檢查（bash）：
   ```bash
   for f in $(find src -name '*.ts' -o -name '*.tsx' | grep -v main.tsx); do
     b=$(basename "$f" | sed 's/\.tsx\?$//')
     grep -rqE "['\"][^'\"]*/${b}(\.tsx?)?['\"]" src tests --include='*.ts*' \
       --exclude="$(basename $f)" || echo "UNREFERENCED: $f"
   done
   ```
4. 未使用的 import 會被 ESLint（`@typescript-eslint/no-unused-vars`）擋下，**不准 disable 註解除非必要**。

## 四、Vercel 部署守則（vercel.json / .vercelignore）

1. **`.vercelignore` 已存在，禁止移除**。它排除：`.git`、`node_modules`、`dist`、`coverage`、`tests/`、`docs/`、`uploads/`、`*.bak/*.tmp/*.old/*.log`、編輯器雜檔等。新增頂層檔案/資料夾時，先判斷「生產 build 需不需要它」，不需要就加進 `.vercelignore`。
2. **`vercel.json` 保持極簡且明確**（現況）：
   ```json
   {
     "framework": "vite",
     "buildCommand": "npm run build",
     "installCommand": "npm ci --no-audit --no-fund",
     "outputDirectory": "dist",
     "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
   }
   ```
   - `outputDirectory: dist` 確保**只有最終靜態產物**（~800 KB）成為部署內容，不會把整包開發環境上傳成 deployment。
   - SPA fallback（BrowserRouter）靠 `rewrites`，不准改成 `cleanUrls`/`trailingSlash` 等會動到路由行為的設定。
   - 不需要的欄位（`env`、`crons`、`regions`、`headers` 等）**不要加**；除非有明確需求。
3. `dist/`、`node_modules/`、`.vercel/` 已在 `.gitignore`，**不准 commit 進去**。
4. 部署產物体积預算：`dist/` gzip 後總量 **≤ 500 KB**（現況約 220 KB gzip）。超出時先檢查：是否有人把大套件/大圖塞進 bundle、lazy loading（`App.tsx` 的 `React.lazy` 分包）是否被破壞。

## 五、程式品質守則（防止「隱形增肥」與回歸）

1. **每次 PR 必跑且必綠**：
   ```bash
   npm run check   # = tsc -b && eslint . && vitest run（型別 + lint + 52 項測試）
   npm run build   # 生產打包，確認無報錯
   ```
2. `react-hooks/set-state-in-effect` 已刻意降級為 **warn**（見 `eslint.config.js` 註解）：各遊戲「示範模式」的編排 effect 是刻意的同步 setState + timeout 推進模式，有測試覆蓋。**不准為了消 warning 重寫這些 demo effect**（高回歸風險）；但新程式碼應優先採用 `useRoundEngine.ts` 的「全部轉換都在 timeout 回呼內」寫法。
3. 事件監聽、`setInterval`/`setTimeout`、`URL.createObjectURL` 必须有對應清理（`removeEventListener`/`clear*`/`revokeObjectURL`）。參考正例：`src/apps/photo/lib/useObjectUrl.ts`。
4. Web Audio 音效維持**合成**（`gameSound.ts`、`photo/lib/sound.ts`），不准引入 mp3 音效檔。
